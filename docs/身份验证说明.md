# 模块身份验证说明（x-model-Authorization）

> 适用范围：集市开发者平台 `/api/open/*` 全部模块公共 API，以及经 `/api/open/invoke/:apiId` 的平台代理调用。
>
> 设计目标：**只允许「已注册模块」发出的请求访问**，其他任何来源（浏览器直连、脚本裸调、未注册服务）一律 401/403。全程只需在请求头加一条 `x-model-Authorization`，不需要传其他字段。

---

## 1. 总体机制

```
┌──────────┐   ① 本模块用 SM2 私钥签发 token      ┌────────────────┐
│ 模块服务  │ ──────────────────────────────────→ │ 开发者平台      │
│ (持有私钥) │   ② 请求头: x-model-Authorization   │ (存有模块公钥)  │
└──────────┘   GET /api/open/...                 └────────────────┘
                                                   ③ 用该模块公钥验签
                                                   ④ 校验时间窗 + nonce 防重放
                                                   ⑤ 校验 grants 授权
```

- **非对称签名**：模块注册时平台为每个模块生成一对 SM2 密钥；私钥仅模块侧持有，公钥存平台。伪造请求无法通过验签。
- **授权分离**：认证（是谁）与授权（能调什么）分开。认证通过后，平台按 `module_api_grants` 校验该模块是否被授予目标 API 的权限码（scope）。

## 2. 请求头格式

```
x-model-Authorization: base64url(slug).base64url(ts).base64url(nonce).base64url(sign)
```

| 段 | 含义 | 说明 |
|----|------|------|
| `slug` | 模块标识 | 注册模块时的 slug（如 `my-service`） |
| `ts` | 毫秒时间戳 | 与服务器偏差需 ≤ **5 分钟** |
| `nonce` | 随机串 | 一次性，5 分钟窗口内不可重复（防重放） |
| `sign` | SM2 签名（hex） | 对拼接串 `"{slug}\n{ts}\n{nonce}"` 签名，`hash: true`，非 DER |

### 2.1 生成 token（Node.js 示例）

```javascript
const sm2 = require('sm-crypto').sm2

const SLUG = 'my-service'        // 你的模块 slug
const PRIVATE_KEY = '<你的模块私钥>' // 模块 API 页获取，仅存服务端

function buildModelAuthorization() {
  const ts = String(Date.now())
  const nonce = Math.random().toString(36).slice(2, 12)
  const payload = `${SLUG}\n${ts}\n${nonce}`
  const sign = sm2.doSignature(payload, PRIVATE_KEY, { hash: true, der: false })
  const b64u = (s) => Buffer.from(s, 'utf8').toString('base64url')
  return `${b64u(SLUG)}.${b64u(ts)}.${b64u(nonce)}.${b64u(sign)}`
}

// 每次请求都重新生成（nonce 不可复用）
fetch('https://developer.ssemarket.cn/api/open/me', {
  headers: { 'x-model-Authorization': buildModelAuthorization() },
})
```

> 平台「模块 API」页的 **生成认证令牌** 按钮可以实时产出一个 token 供快速联调（5 分钟内有效）。

### 2.2 调用示例

```bash
TOKEN=$(node -e '...上面的 buildModelAuthorization()...')

# 本模块信息（self 组默认授权，注册即可用）
curl -H "x-model-Authorization: $TOKEN" \
  https://developer.ssemarket.cn/api/open/me

# 调用已授权的对外 API（经平台代理，apiId 见 API 广场）
curl -X POST \
  -H "x-model-Authorization: $TOKEN" \
  -H "content-type: application/json" \
  -d '{"orderId":"123"}' \
  https://developer.ssemarket.cn/api/open/invoke/42
```

## 3. 密钥管理

- **获取**：模块注册成功后即自动生成密钥对。「模块 API → 选择模块 → API 调用凭证（SM2）」页可查看公钥与私钥。
- **存放**：私钥只放模块服务端（环境变量/密管系统），**不要**放进前端代码或仓库。
- **轮换**：凭证页「轮换密钥」立即生成新密钥对，旧私钥马上失效（无需通知平台，公钥同步更新）。
- **离线生成**：`node server/scripts/gen-module-key.cjs` 可离线生成密钥对，再用管理台写入模块（适合密钥不出本机的场景）。

## 4. 平台校验流程（服务端行为）

收到带 `x-model-Authorization` 的请求后，平台按顺序校验：

| 顺序 | 校验 | 失败返回 |
|------|------|---------|
| 1 | 头存在且为四段 base64url | 401 格式无效 |
| 2 | slug 对应模块存在、已启用 | 401 模块不存在或已停用 |
| 3 | `ts` 与服务器偏差 ≤ 5 分钟 | 401 时间戳超出允许偏差 |
| 4 | SM2 公钥验签通过 | 401 SM2 验签失败 |
| 5 | nonce 5 分钟内未出现过 | 401 nonce 已使用，疑似重放 |
| 6 | grants 含目标 API 的 scope | 403 模块未被授权调用 |

**鉴权通过 ≠ 全部放行**：认证只证明「请求来自该模块」，能不能调某个 API 还要看第 6 步的授权（grants）。

## 5. 模块对外提供 API 时如何验证调用方

你的模块把接口登记到平台（模块 API → 对外提供 API）后，其他模块经平台代理 `/api/open/invoke/:apiId` 调用你。平台在转发时**用平台私钥重新签发**并附带：

| 请求头 | 含义 |
|--------|------|
| `x-model-authorization` | **平台签发的认证 token**（slug 段固定为 `__platform__`，证明请求来自本平台中转） |
| `x-invoker-module` | 实际调用方模块 slug（明文，便于日志与业务区分） |

### 5.1 平台公钥（验证平台身份用）

```
04f01e80d1f5218eb28dc223577f74725552ea30f38dc4d2e7bb03ecbabea509d33f9815ac63a5c930fc5cbd575684ea44067c249b85d51e4afe3df2af5fc09cf0
```

> 该密钥对内置在平台 `server/.env` 可覆盖（`PLATFORM_SM2_PRIVATE_KEY` / `PLATFORM_SM2_PUBLIC_KEY`）。若平台侧轮换了密钥，会同步更新本文档。

### 5.2 模块侧验证代码（Node.js）

只要这段验证通过，即可确认请求**必然来自平台代理**（直连、伪造一律拒绝）：

```javascript
const sm2 = require('sm-crypto').sm2

const PLATFORM_PUBLIC_KEY = '04f01e80...cf0' // 上面的平台公钥
const PLATFORM_SIGNER = '__platform__'

function unb64u(s) {
  return Buffer.from(s, 'base64url').toString('utf8')
}

/**
 * 校验 x-model-authorization：
 * 返回 true 表示请求由平台签发转发（可信任 x-invoker-module 为真实调用方）
 */
function verifyPlatformAuth(header) {
  const parts = String(header || '').split('.')
  if (parts.length !== 4) return false
  const [slug, ts, nonce, sign] = parts.map(unb64u)
  if (slug !== PLATFORM_SIGNER) return false
  // 时间窗 ±5 分钟
  if (Math.abs(Date.now() - Number(ts)) > 5 * 60 * 1000) return false
  const payload = `${slug}\n${ts}\n${nonce}`
  return sm2.doVerifySignature(payload, sign, PLATFORM_PUBLIC_KEY, { hash: true, der: false })
}

// Express 用法示例
app.use('/your-api', (req, res, next) => {
  if (!verifyPlatformAuth(req.headers['x-model-authorization'])) {
    return res.status(401).json({ message: '仅接受平台中转请求' })
  }
  req.invokerModule = req.headers['x-invoker-module'] // 已可信的调用方标识
  next()
})
```

### 5.3 签名串说明

平台签发时对拼接串 `"{slug}\n{ts}\n{nonce}"` 签名，其中 `slug` 固定为 `__platform__`。token 格式与模块调平台 API 的 `x-model-Authorization` 完全一致（base64url 四段），验签参数同样为 `hash: true, der: false`。

> nonce 防重放由平台每次转发重新签发保证（时间戳+随机数），模块侧如需严格防重放可自行缓存 nonce 5 分钟。

## 6. 常见错误对照

| 现象 | 原因 | 处理 |
|------|------|------|
| 401 `缺少 x-model-Authorization 请求头` | 没带头 | 检查请求头拼写 |
| 401 `格式无效（应为 slug.ts.nonce.sign 四段）` | 拼接方式错误 | 检查 base64url 段数与点号 |
| 401 `模块不存在或已停用` | slug 错 / 模块被停用 | 核对 slug、模块状态 |
| 401 `时间戳超出允许偏差（±5 分钟）` | 服务器时钟漂移 | 校时（NTP） |
| 401 `SM2 验签失败` | 私钥不对 / 签名参数错 | 确认私钥与模块匹配；`hash: true, der: false` |
| 401 `nonce 已使用，疑似重放` | 同一 nonce 复用 | 每次请求重新生成 nonce |
| 403 `模块未被授权调用：xxx` | grants 缺少 scope | 在 API 广场申请，或找管理员授权 |

## 7. 安全要点

1. **私钥零上送**：任何接口都不需要（也不应该）上传私钥；签名只在模块本地完成。
2. **重放窗口 5 分钟**：攻击者截获 token 最多重放 5 分钟，且同 token 第二次即被拒。
3. **失败即拒**：以上任一环节失败都不放行，且不泄露模块存在性之外的信息。
4. **最小授权**：模块默认只有 `self`（查自身信息）权限；其他 API 必须在 API 广场申请、审批后才能调用。
